{
  description = "A CI-optimized automation script to run an x86_64 guest kernel hearbeat check inside QEMU";

  inputs = {
    nixpkgs.url = "github:nixos/nixpkgs/master";
  };

  outputs = { self, nixpkgs }:
    let
      host = import nixpkgs { system = "aarch64-darwin"; };
      
      # Pull pre-compiled kernel artifact from the cache
      guestLinuxPkgs = (import nixpkgs { system = "x86_64-linux"; }).linuxPackages;
      kernel_dir = guestLinuxPkgs.kernel;

      # Pull pre-compiled static busybox directly from Nix cache
      guestStaticPkgs = import nixpkgs { system = "x86_64-linux"; };
      busybox_static = guestStaticPkgs.pkgsStatic.busybox;
    in {
      packages.aarch64-darwin.default = host.writeTextFile {
        name = "qemu-boot-busybox-kernel-heartbeat";
        executable = true;
        destination = "/bin/qemu-boot-busybox-kernel-heartbeat";
        text = ''
#!${host.stdenv.shell}
BASE_DIR=$(pwd)
LOG_PATH="$BASE_DIR/test.log"
ERR_LOG="$BASE_DIR/qemu_error.log"

cleanup() {
  echo "Cleaning workspace artifacts..."
  rm -rf "$BASE_DIR/tmp_initrd"
  rm -f "$BASE_DIR/initrd.cpio"
  rm -f "$LOG_PATH" "$ERR_LOG"
  echo "Workspace clean."
}

trap cleanup EXIT INT TERM

echo "--- Step 1: Building minimal initrd ---"
mkdir -p "$BASE_DIR/tmp_initrd/bin"
mkdir -p "$BASE_DIR/tmp_initrd/proc" "$BASE_DIR/tmp_initrd/sys" "$BASE_DIR/tmp_initrd/dev"
mkdir -p "$BASE_DIR/tmp_initrd/etc"

cp "${busybox_static}/bin/busybox" "$BASE_DIR/tmp_initrd/bin/busybox"
chmod +x "$BASE_DIR/tmp_initrd/bin/busybox"
ln -sf busybox "$BASE_DIR/tmp_initrd/bin/sh"

cp "${busybox_static}/bin/busybox" "$BASE_DIR/tmp_initrd/init"
chmod +x "$BASE_DIR/tmp_initrd/init"

# Direct command calls in inittab (No shell used)
cat <<EOF > "$BASE_DIR/tmp_initrd/etc/inittab"
::sysinit:/bin/busybox mount -t proc proc /proc
::sysinit:/bin/busybox mount -t sysfs sysfs /sys
::sysinit:/bin/busybox mount -t devtmpfs devtmpfs /dev
::sysinit:/bin/busybox cat /proc/version
::sysinit:/bin/busybox cat /proc/cpuinfo
::sysinit:/bin/busybox cat /proc/meminfo
::sysinit:/bin/busybox poweroff -f
EOF

# Pack the directory tree entries
cd "$BASE_DIR/tmp_initrd"
find . ! -name "." | ${host.cpio}/bin/cpio -oH newc > "$BASE_DIR/initrd.cpio"
cd "$BASE_DIR"

echo "--- Step 2: Running Automated QEMU Instance ---"
> "$LOG_PATH"
        
${host.qemu}/bin/qemu-system-x86_64 -cpu max -kernel ${kernel_dir}/bzImage -initrd ./initrd.cpio -nographic -display none -no-reboot -serial file:"$LOG_PATH" -append "console=ttyS0 init=/init panic=-1" -m 512M 2> "$ERR_LOG"

echo "--- Step 3: Verifying Results ---"
if [ -s "$LOG_PATH" ]; then
  echo "--- Captured Guest Logs ---"
  cat -n "$LOG_PATH"
          
  # Verify that the specific system files were read successfully
  if grep -q "Linux version" "$LOG_PATH" && grep -q "model name" "$LOG_PATH" && grep -q "MemTotal" "$LOG_PATH"; then
    echo "CI STATUS: SUCCESS"
    exit 0
  else
    echo "CI STATUS: FAILURE (Diagnostics missing from log)"
    exit 1
  fi
else
  echo "CI STATUS: ERROR (Empty Log Layout)"
  [ -f "$ERR_LOG" ] && cat -n "$ERR_LOG"
  exit 1
fi
        '';
      };
    };
}

### Part 2: The Hardware Language (x86_64 vs. ARM64)
Computers "speak" different languages at the electrical level. These are called **Instruction Set Architectures (ISA)**.

*   **x86_64 (The Standard):** This is the language of Intel and AMD processors. It powers almost all traditional servers and most Windows/Linux desktops.
*   **ARM64 (The Modern Alternative):** This is the language of mobile phones, Raspberry Pis, and now **Apple Silicon (M1/M2/M3 chips)**.
*   **The Conflict:** An ARM64 chip (your Mac) cannot natively "understand" x86_64 instructions. It’s like trying to read a book written in Japanese when you only know French.

**The Deep Dive:** Because we are running an **x86_64** kernel on an **ARM64** host, we cannot do "Virtualization" (which is fast). We must do **"Emulation"** (which is slower but works). We are essentially building a software "translator" that converts x86_64 instructions into ARM64 instructions in real-time.

---

### Part 3: The Engine (Linux Kernel & QEMU)
How do we bridge the gap between the hardware language and the software?

*   **QEMU (The Emulator):** Think of QEMU as a "Software Computer." It simulates a motherboard, a CPU, memory, and hard drives. Because it is an emulator, it can trick an x86_64 OS into thinking it is running on an Intel chip, even though it's actually running on your Mac's ARM chip.
*   **The Linux Kernel:** This is the "Manager" of the operating system. It doesn't know how to "run an app"; it only knows how to talk to the hardware (CPU, Memory, Disk). Our script checks the kernel to see if it can successfully "take over" the virtual hardware.
*   **Initrd & BusyBox (The "Starter Kit"):** 
    *   Normally, a computer boots from a hard drive. But for a test, we don't want to deal with disk partitions. 
    *   **Initrd (Initial Ramdisk):** We create a tiny "temporary hard drive" that lives entirely in the computer's RAM. 
    *   **BusyBox:** A tiny, "Swiss Army Knife" version of Linux tools. We put just enough of it in the Initrd to print the system's health and then turn the power off.

---

### Part 4: The Factory (Nix)
How do we make this happen automatically and reliably?

*   **Nix (The Build System):** Most developers use tools like `pip` or `apt` to install software. These are "imperative"—they just grab the latest version and hope it works. **Nix is "Functional."**
*   **Determinism:** In Nix, if you give it the same "recipe," it will produce the *exact* same result every single time, down to the last bit. It creates a "pure" environment.
*   **The Nix Store:** When the script asks for a "pre-compiled kernel," Nix doesn't download it every time. It looks in a "Store" (a massive warehouse of pre-built software). If the kernel is already there, it grabs it instantly.

**The Deep Dive:** Nix handles the "Dependency Hell." It manages the fact that we need `aarch64-darwin` tools to run the script, but `x86_64-linux` binaries to run the test. It keeps these two different worlds completely isolated so they don't break each other.
